rackrank · a tour of the code

Which seven tiles will you actually draw?

Some racks turn up far more often than others. rackrank counts how many ways the bag can deliver every seven-letter rack, sorts them, and turns the likeliest into flash cards. Every demo below runs the same arithmetic as the Python.

Count the ways to draw a rack

probability.py

A draw is one particular set of physical tiles from the bag. The bag holds nine As, so a rack with two As can arise in C(9, 2) = 36 ways. Across a whole rack the ways multiply, and the product is the rack's draw count. Type any seven letters.

Blanks

Blanks. With one blank, a rack of AEINRS? can spell AEINRST, but so can AEINRT?, AEINST? and others. For each distinct letter a blank could stand for, the leftover concrete tiles are a different rack. Those racks never overlap, so alphagram_draw_count adds them up. Repeated letters (the two Es in AEEINRT) are counted once, which is what the set(combinations(...)) is for.

Blank mode 0 does not pretend blanks don't exist. They are still in the 100-tile bag, so the "1 in N" odds above use C(100, 7). The mode only picks which racks count.

Group words by alphagram

lexicon.py

An alphagram is a word's letters in alphabetical order. Every anagram of a rack shares one, so a dictionary grouped by alphagram gives you the answer to "what can I make from these tiles?". Pick a word to see its siblings.

The same module answers the hook question without a separate table. A back hook is a letter that makes another valid word when added after: back_hooks("STAINER") tries A to Z against the dictionary and finds S. The loader reads one word per line, with an optional definition after a tab or space, and new formats plug in through LOADERS.

Rank, then filter

ranking.py

Every alphagram is scored, sorted by descending draw count with ties broken alphabetically, and numbered from 1. Filters run afterwards and only hide cards, so a card keeps its rank whatever you select. Switch the blank mode to watch the order change, or filter to single anagrams to watch the ranks stay put.

Blanks

Eleven sample alphagrams. Bars are on a log scale: ZOOLOGY has 1,344 draws, AEINORT millions.

Racks the bag cannot supply are dropped. A second style, --front rack, lists the racks themselves (letters held plus a ? per blank) instead of alphagrams.

Turn a rack into an Anki card

export/

Racks with a few anagrams become Basic notes. Racks with many become Cloze notes, with each anagram hidden behind a deletion. Drag the cut-off, and tap a deletion to reveal it.

The first field is always the alphagram. Anki treats it as the note's identity, so importing again updates cards instead of duplicating them. tsv.py writes tab-separated files with Anki's header lines, and apkg.py builds a package with genanki, using IDs derived from a CRC of the names so repeated exports line up.

Fill in missing definitions

definitions.py

--fetch-definitions only looks up the words in the cards being exported. It asks dictionaryapi.dev, falls back to Wiktionary, and writes what it finds back into your word list. The web services are not Collins and they push back, so the loop is built to cope. Run a simulated 40-word lookup.

definition found not found (saved to .nodef) service error, skipped backing off

A rate limit makes _fetch_with_backoff wait 20 seconds, doubling each time, up to five retries on the same word. A 5xx error skips the word without remembering it, so the next run tries again; five in a row stops the run. Progress is written in a finally block, and the dictionary is replaced through a temporary file so an interruption can't leave it half written. The simulation runs about 40 times faster than real waits.
